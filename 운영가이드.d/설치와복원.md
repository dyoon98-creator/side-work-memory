## 7. 점검·업데이트·백업

`status`가 `Side is not running. Open Side.app.`을 반환하면 먼저 앱 실행 여부를 확인한다. 설치 실패와 같은 뜻은 아니다. `doctor`는 권한·라이브러리·모델 등을 점검하지만, 제공자가 설정되어 있으면 합성 문장으로 연결 검사를 할 수 있다. 외부 호출을 원하지 않으면 제공자 설정을 먼저 확인한다.

재빌드에는 Bun, Xcode, FTS5·확장 로딩을 지원하는 SQLite가 필요하다. 현재 설치는 Bun 1.4.2로 빌드했다. 빌드 시 모델 다운로드가 발생할 수 있다.

```sh
cd /Users/dongchanyoon/Documents/Work/Projects/85.side-work-memory
git status --short
bun install --frozen-lockfile
bun run build
```

업데이트 전에는 Side를 정상 종료하고 기존 앱을 별도 `.noindex` 폴더에 보관한다. 새 앱을 복사한 뒤 서명을 확인한다. 임시 서명 빌드이므로 업데이트 후 권한을 다시 묻거나 Keychain 접근이 달라질 수 있다. 권한 우회나 ‘모든 앱 허용’으로 해결하지 않는다.

데이터 백업은 앱 종료 후 데이터 루트 전체를 접근 제한된 로컬 저장소에 복사한다. DB만 복사하면 관련 파일이나 WAL을 빠뜨릴 수 있다. 암호화 키는 Keychain에 있으므로 데이터 폴더만으로 다른 Mac에서 복원된다고 가정하면 안 된다. 키 값의 출력·내보내기는 수행하지 않는다. 장기 사용으로 데이터가 1GB 이상 커지면 프로젝트 저장구조 규칙에 따라 외장 SSD 이관을 별도 검증한다.
